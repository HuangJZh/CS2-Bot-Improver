BotController 的已确认接口变化包含 AbiVersion → ApiVersion、SubtickMove.Button 从 uint → ulong、移除部分默认兼容实现，并调整按键注入/抑制/移动控制。这些变化要求成组适配。

我们当前 NadeSystem 的投掷回放通过投射物快照生成实体，不能仅因 SubtickMove 变化就判断所有道具数据库必须重录。录制工具和真正消费该结构的模块需分别检查格式。

我们的 BotAimImprover、BotState、NadeSystem 已展开为定制源码目录，上游仍将它们作为 gitlink 子模块。整仓合并存在目录/子模块结构冲突，也不能靠 submodule update 更新这些定制目录。

## 每次更新的固定流程

1. **固定稳定恢复点**。记录当前稳定提交、配置、难度包、导航与道具数据及实际安装文件哈希。同步个人仓库稳定分支并标记稳定版本。
2. **读取固定发布标签**。保留原样的上游基线，比较精确提交和所有子模块指针。候选版本在 upgrade/base-vX.Y.Z 之类的隔离分支处理。
3. **按模块三方审查**。对比旧上游源码、新上游源码和我们的定制模块。兼容性修补与玩法变化分别提交，给每项变化记录采用、已包含或暂缓及理由。
4. **锁定兼容组合**。清单同时记录 CS2 构建、基础发布提交、CSS/Metamod、子组件提交、API 契约版本、二进制 SHA256、自定义提交和数据格式版本。仓库指针与实际安装清单分别记录。
5. **先适配候选环境**。退出游戏后安装一致的依赖组合，用其 API 编译自定义模块。底层依赖跨接口更新采用完整重启，并核验签名解析及必要的偏移验证。
6. **执行固定回归场景**。检查 MIX/HEAD、定位和真实出弹、转身朝向保护、声音/视觉优先级、队友 0.75 与精英配置、互穿、轮盘发枪、道具库存消费、闪光效果、路径与回合学习。另检查切图、重开、玩家接管和前端二次启动。
7. **生成定制升级包并部署**。保存候选验证记录和完整升级前备份，安装文件全部校验后才将候选标记为稳定。个人仓库保存代码与锁定清单，大型运行包另行备份。

上游发布后先进入评审队列。用户使用我们验证过的定制升级包，配置合并应明确保留拟人后端、队友系数、互穿、选点和库存规则。

## 回退边界

当前 CS2 构建兼容时，可以恢复整套上个稳定组合。若游戏已经改变了签名/内存布局，旧包可能同样失效，此时应停用受影响的挂钩模块或采用兼容修补版本。地图资源变化还需另行检查导航校验和与投掷点。

部署记录应支持选择性恢复玩法，而基础框架与接口相关组件应保持为已验证的一组。这样可撤回不合适的 AI 行为，同时维持对当前游戏的兼容性。
