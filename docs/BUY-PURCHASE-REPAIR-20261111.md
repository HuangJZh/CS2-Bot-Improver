# 机器人重复买枪与偏好修复

2026-11-11，在 v1.4.8 + Custom 8.50 基线上修复购买模块；瞄准、反应、移动和战斗强度不变。

## 根因

Camper 模板把 XM1014、Negev 与其他喷子排在主流步枪/AWP 前面；插件又会以 50% 概率将新买的 XM1014 换成 Negev。下一回合原生购买仍想买偏好更高的 XM1014，于是可能丢掉保存的 Negev，再被插件换回 Negev，形成浪费资金的循环。Rusher / Duelist 等模板也有资金充足时仍先选中低价枪的排序。

BotBuy 的 HasPrimaryWeapon 只看 ActiveWeapon，切刀/手枪会误判没有主武器，还漏了 MAC-10、SG553、连狙等类别。这会导致自动发枪寻找错误的目标。Buy 本身没有阻止再次购买同槽主武器，多个定时替换分支也没有统一保护保存下来的枪。

## 修正

- 三档难度共 24 组武器模板移除 AUG、SG553；AK / M4A1-S / M4A4 / AWP 排在预算枪之前，狙击模板仍将 AWP 排第一。只更改 WeaponPreference，其他配置字段逐文本比对未变。
- 主武器检查改为遍历完整背包。保存下来的主武器在回合开始建立保护快照，用已安装 BotController 的购买接口限制该机器人的原生购买只补必要护甲/拆弹器，不重新买主武器。
- 插件自身拒绝重复主武器购买、相同武器替换、保存枪的退款/替换。创建失败不扣钱；旧回合的延迟购买回调会失效。保护购买计划在结束回合、断开、换图和卸载时释放；显式 bot_loadout 模式保持独立。
- 删除富裕时随机把好枪替换成 M249 / 连狙的分支。新买的 AUG / SG553 可转换为本方主流步枪；已有或捡到的枪不会因为禁止购买而强行消失。
- BotSupport 的发枪备选同步删除 SG553，AWP 买不起时可回退 AK。AUG 原本已排除。

## 验证与安装

购买策略 52 项、发枪策略 35 项通过；三档全部模板的排除项、主武器优先顺序与重复项检查通过。VPK 重打包经过 CRC 和完整条目往返比对，只替换 botprofile.db。

已安装 BotBuy 1.0.14-custom.2、BotSupport 1.0.9-purchase-fix 和三档 VPK；活动难度保持 Medium。修改前的二进制和难度包位于 D:/codespace/CS2-Bot-Improver-backups/buy-fix-20261111/before。

BotBuy 从固定上游子模块展开为定制源码，后续更新必须保留此修补。依赖清单仍固定在 base-v1.4.8.lock.json，新增 purchase-fix-20261111 标记及实际安装摘要。测试数据保留本地，不提交个人账户、日志或临时测试插件。

受控实机核验：三次回合开始检查中，Negev / XM1014 / MAC-10 / 主流步枪 / AWP 五个测试对象共 15 次实体句柄均保持不变；插件的购买保护计划成功建立。以 10000 加时资金重开后，9 个机器人均有主武器，其中 8 个为 AK/M4/AWP，另一个为原有低概率连狙分支；没有 AUG/SG553，探针无异常。该结果确认保存枪与正常新购能够并存，不能用这一次样本推算全局购枪概率。

部分受控回合是冻结阶段主动重开事件，没有覆盖普通完整对局的原生经济决策。因此只将其作为持枪保护与插件购买路径的核验；三档原生优先顺序另由配置检查验证。临时测试插件已移走，测试挂载逐字节恢复。
