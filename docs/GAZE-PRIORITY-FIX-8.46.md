# 8.46：声音、战斗和前进视角的优先级修复

日期：2026-11-04。修复声音调查时视角反复被前进方向抢走，以及已看见敌人仍跟随其他声音的问题。

## 根因和修改

旧版声音保护依赖 HumanState 的采样结果。初次发现目标、模型尚未建立、短暂遮挡或原生 Enemy 句柄闪断时，这个保护可能暂时失效。另一个问题是声音转向只在每帧第一次回调有效，后续原生寻路/视角更新仍可能覆盖它；同一帧缓存的声音转向也没有在视觉接管时完整作废。

本次修改：

- 用实际视野、烟雾和遮挡检查确认可见威胁，保护不再等待瞄准模型的延迟队列。完整模型的可见点采样也会确认视觉优先级，覆盖仅露头顶等局部暴露。
- 确认可见威胁时，清除旧声音、调查窗口、声音持有的待执行角度和转向缓存。最后写入视角前再次检查，避免同一帧内敌人已经出现、旧声音角度仍在稍后执行。
- 最近在交战中实际开火时，保留短暂的射击关注，避免声音调查干扰连续开火与原生后坐力。
- 短暂丢失视觉保留 220ms 的注意力保护；原生 Enemy 句柄暂失时，先处理近期视觉记忆，再考虑声音或地图预瞄。
- 声音关注期间，原生 Update、Upkeep、UpdateLookAngles 的结束阶段都使用同一帧缓存的同一角度。重复回调只重申同一结果，不重复增加转身步长，防止寻路和声音交替抢视角。
- 新声源有独立的反应截止时间；同一声源持续响动不重置反应等待。脚步变为枪声时保留连贯的方向误差，减少位置估计突变。
- 声音调查留出反应结束后至少约 650ms 的观察窗口；连续声源单次最多占用约 1.6 秒。调查结束后，同一声源约 700ms 内不立即重复拉走视角；脚步升级为枪声可打断这个重复检查间隔。
- 安包、拆包和其他插件的视角控制优先；声音不在这些动作中争夺视角，待执行步骤也会再次检查目标动作。

上一版 20% 的转身速率倍率、三档基础反应时间和朝向开火保护保留。普通目标选择、伤害和武器射速没有调整。

## 检查与实机证据

234 项检查通过，包含声音合并、独立声源反应计时、连续声源稳定关注、关注超时、重复检查间隔和枪声升级。构建为 0 警告、0 错误。

独立 Dust2 回归场景使用固定位置、禁止移动和开火、隐藏声源以及脚本化 weapon_fire 事件，分别检查无可见敌人的声音调查、可见敌人与无关声源同时存在、150ms 短暂遮挡后重新出现。该场景用于视角优先级验证，不是自然听觉或弹道命中率测试。

- 8.45 在敌人重新出现后仍出现约 **27.04°** 的无关转向；修改后的对照为约 **0.20°**。
- 修改后的可见阶段最大水平偏差约 0.19°，短遮挡阶段约 0.16°。
- 视觉接管以后，没有声音转向步骤继续执行；声音持有期间没有同帧写入不同声音角度的记录。
- 无可见敌人的声音关注窗口中，能完成并保持声音调查，再按期限交还原生控制。该脚本没有穷尽所有地图、声源组合和自然战斗情况。

使用用户原来的 Medium、敌我强度、道具和导航设置，完成两段各 35 秒的自然对局检查：22,304 条非热身/非冻结观察、71 次枪械开火、27 次伤害、7 次击杀；未发现“已开枪后对同一目标重新进入首次反应等待”的回退。最后补充了目标动作开始瞬间的待执行视角检查，并重新通过编译和策略检查。

证据目录：`E:/csdemo/bot-captures/attention-fix-8.46-20261104`。主要对照为 `baseline` 和 `candidate-verified`；自然检查为 `natural-verified`。旧版没有单独记录 sound_gaze_step，不能把旧版该字段的缺失当作实际执行次数为零。

安装版本：BotAimImprover `2.1.8-human.8.46-experimental`。仅替换该模块的 DLL/PDB/deps，用户配置和难度包保留。测试用的配置、gameinfo 和临时插件已恢复。

关闭 CS2 后，运行证据目录中的 `Restore-Previous.ps1` 可恢复 8.45，保留用户配置。源码保存在本地个人仓库，没有向上游推送或提交 PR。
