# Mixed 爆头偏低排查（2026-11-01，human.8.31）

用户澄清：重点是实际爆头太少，不是要求计分板必须出现非零。

## 确认与修复

Mixed 的选点路径已经是除 AWP 外头部优先，两处实现一致。更直接的问题在跟踪预测：旧模型在观测年龄之外，额外增加 `distance / BulletSpeed`，人为假设步枪子弹速度 3000 单位/秒，并最多外推 350ms。模型已经补偿观测延迟，这个额外飞行项又把移动目标往前推了一段，偏差远大于头部尺寸。本次移除此项及未测量的武器弹速表；保留按观测年龄的外推、难度预测系数、反应时间和人为瞄准误差。

以下是相同种子、250u/s 匀速横移、1200u 横向距离的合成模型对照。数值是模型相信的目标方向相对于当前真实位置的平均角误差，**不是游戏实测爆头率**：

| 难度 | 修改前 | 修改后 |
|---|---:|---:|
| Low | 1.407° | 0.440° |
| Medium | 2.404° | 0.161° |
| High | 2.893° | 0.044° |

600/1200/2400u 的回归检查覆盖感知延迟补偿和不同武器类别的相同命中扫描目标方向；69 项模型检查通过，插件编译零警告零错误。

另外补齐诊断缺陷：原来 `eventHitgroup` 参数接收后没有序列化，所谓“已记录命中部位”的说明不成立。现记录真实命中部位、攻击者爆头击杀事件、计分板击杀/爆头数，并保留下一帧计分板读数避免事件时序误判。增加相信的目标方向和敌方眼高，用于区分选点与实际视角执行偏差。交互式 Windows 本地房主（`-steam`、非 `-dedicated`、真人 slot0）可从自己的控制台启动记录；专用服仍只接受服务器控制台。

## 对照和边界

- 独立测试服做过一次**脚本固定瞄头**对照：AK 命中 `hitgroup=1`、`headshot=true`，随后计分板 kills=1、HeadShotKills=1。只证明伤害与统计能记录爆头，不能证明 Mixed 模型合格。
- 独立服没有真人时的自然接敌样本无效；强制敌人句柄/一次性摆视角样本也不能充当自然对枪证据，均保留原始资料但不作爆头率验收。
- 当前开枪决策仍主要检查预定方向，没有用实际视角误差严格阻断开枪。这个已知执行差距可能继续降低爆头率；本次没有贸然加硬门槛，避免重现 Bot 长时间不射击。删除错误提前量不是宣称所有低爆头问题已经解决。

测试与旧安装备份：`E:/csdemo/bot-captures/mixed-headshot-audit-20261101`。其中 `model-comparison` 保留修改前后的完整纯模型与同一对照程序，`probe-runtime/head-events.jsonl` 保留脚本对照原始事件。没有修改用户难度、购买逻辑或其他插件。

## 本地真人房主的自然对局复核

随后启动独立的交互式本地 Mirage 对局（Medium、Mixed、DirectViewControl=false），真人房主留在出生区，Bot 自行寻敌、瞄准、射击，没有强制感知、摆头或攻击注入。通过房主控制台启动采集，已经确认 8.31 和新增诊断字段生效。

- 第一段 60 秒：73 次开火、15 次伤害、5 次击杀，其中 3 次爆头；包括 AK 的 3 次击杀/2 次爆头和 USP 的 2 次击杀/1 次爆头。53 次开火时最近选点为 HEAD。
- 第二段补充步枪场景：仅在测试对局临时将起始资金设为 10000、冻结设为 1 秒并重开回合，让 Bot 自行买枪。最终 67 次开火、18 次伤害、7 次击杀（AK 3、M4A1-S 4），其中 5 次爆头（AK 2、M4A1-S 3）。51 次开火时最近选点为 HEAD。结束时停止采集，起始资金/冻结恢复为 800/15；未写入配置文件。
- 实际爆头事件及下一帧计分板字段均已写入，证据见 `listen-first-summary.json`、`listen-rifle-summary.json` 与对应原始采集。两段采集均正常结束。
- 第二段 HEAD 样本开火回调中，实际视角相对模型输出的角差中位约 1.51°。这不是精确子弹射出角度，但说明实际执行仍可能落后于模型；本次没有通过强制锁头来掩盖这个差距。

7 次步枪击杀/5 次爆头是小样本功能验证，不是新模型长期爆头率，也不是同场景修改前后的统计对照，不能把它当作提升百分比。安装仅更新 BotAimImprover；修复版已在当前测试对局加载，旧版 8.30 已备份。
