# Custom 8.57：回防开火、已有武器转交与跨阵营燃烧物

## 下包后不开火

修复并加固以下实际代码路径：

- BotState 旧的胜方切刀逻辑使用 GetPlayers，可能受 BotHider 和客户端名单限制而漏算存活敌人。改为完整控制器实体列表；回防树工作期间不再施加胜方切刀锁，并释放本模块此前留下的切刀锁。
- 原生 BT 在请求开火前读取武器冷却。已有有效的 usercmd 攻击抑制时，回防模式不再重复把武器冷却向后推；保留反应、视线、朝向和实际按键抑制。旧状态机及输入钩子未绑定时的保护不变。
- 为局部遮挡加入有预算的手臂、腿部等可见点检查：最多每 100 ms 为一个轮转候选增加扩展采样，不逐帧对所有敌人做全身搜索，也不把隐藏坐标交给模型。
- 回防 BOT 背包有枪但活动武器为空时，限频请求原生 EquipBestWeapon。初始化入口仍受当前 server.dll 哈希保护。
- 若模型连续至少 600 ms 明确允许、视线和朝向有效、枪械有弹且冷却就绪，却没有射击进展，允许一次短促攻击恢复；它不能授予射击许可，换目标、换武器、失去许可或发生真实射击会重置等待。狙击枪还要求已开镜。脉冲自动过期并在状态退出时取消，不绕过其他模块的攻击抑制。
- BT 手枪按住攻击的原生周期由 0.2 s 恢复为 0.95 s，避免需要蓄力的手枪不断被过短周期打断；模型反应与开火门控仍生效。

未将回防模块改成另一套自造战术树，四个 Valve 目标模块和原先攻击优先顺序保留。Low/Mid/High 敌人 250/190/140 ms 及队友相对 0.75 设置没有调整。

## 资金不足时发已有主武器

先沿用现有购买顺序：最富的合格队友为玩家购买可负担的枪，包括原有低预算步枪/冲锋枪降级选择。只有无人买得起可选枪时，才在附近、未交战、购买区内的合格机器人队友中，按现有主武器的实时 VData.Price 选择最贵的一把转交。

通过原生掉落原武器并放到请求者附近，不创建新武器、不扣钱。保留原实体、弹量和物品属性。金额相同时优先距离近者；不拿其他真人队友的武器。原有购买时间、请求冷却及玩家无主武器条件保留。新增枪支仍遵守狙击名额，已有枪在队内转交不增加名额。

## 跨阵营燃烧物重复购买

旧 FindInventoryGrenade 按持有人阵营选择唯一类名：CT 只找 incgrenade，漏判捡来的 molotov。

- 两种火统一占用同一个库存类别，不受持有人阵营影响。购买、可投掷判断和库存扣除均使用统一识别。
- 投掷时按实际持有的种类选择物品定义和广播，不把捡来的 T 火悄悄变成 CT 火。
- GiveNamedItem 后检查新物品是否真的进入背包；若只生成了未被接收的地面新物品，删除该次新生成物并退款，避免购买看门狗持续制造地面垃圾。不会清理玩家已有的地面投掷物。
