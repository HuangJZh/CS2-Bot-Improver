# Custom 8.54：接入真正的 Valve 回防行为树

## 确认与纠正

游戏包实际包含 `scripts/ai/retakes/bt_default.kv3`，与竞技模式默认的旧状态机不是同一条决策入口。回防 cfg 使用 `mp_bot_ai_bt` 指向该文件。此前只根据公开更新日志，将两者概括成同一套原生逻辑并不准确。

本次直接引用当前游戏包里的四个模块，没有用旧竞技 AI 改名替代：

- `scripts/ai/retakes/modules/bt_defuse_planted_bomb.kv3`
- `scripts/ai/retakes/modules/bt_hide_near_planted_bomb.kv3`
- `scripts/ai/retakes/modules/bt_hold_near_planted_bomb.kv3`
- `scripts/ai/retakes/modules/bt_watch_approach_points.kv3`

自定义的 `scripts/ai/custom_improver/retake.kv3` 只负责接线，引用 Valve 原模块以及其记忆、调查和攻击模块。Valve 资产本身没有复制进个人仓库或覆盖游戏包。

## 启用范围

在经典休闲或竞技的 C4 下包后启用；下包前保留原有进攻、买枪和下包流程。不是把整局改成回防游戏规则，也不覆盖死亡竞赛、Rush 或原生回防模式已有的行为树。

运行中只改 `mp_bot_ai_bt` 不会给已存在的 BOT 创建行为树。本次调用已在当前 Windows server.dll 中验证的原生 AI 初始化入口重新创建每个 BOT 的树，并检查原生树指针非零。游戏模式、队伍、玩家 Pawn 和持有武器不需要因此重建。

原生入口及树指针布局绑定 server.dll SHA256 `84d596644ad574ac70f427777c89f9006a8023f493c46f4c215f40bceef13cbb`。后续游戏更新导致哈希变化时，接入层会拒绝使用旧入口，保留原有 AI 并记录提示；不能当作已经跨版本兼容。

## 与我们的系统结合

- 真正的回防树负责推进、独占拆包、炸弹周边选位、驻守和观察路线。
- 接入期间暂停自定义全局分路、支援调动和静步探身，并停止旧假拆与移动状态修改，避免抢夺目标/移动控制。
- 回防树不填写旧的 Enemy 字段，直接开启会使旧瞄准模型没有目标。本次增加严格 FOV、视线和烟雾检查的目标桥接，把真正看到的目标交给原有模型；未把不可见敌人的坐标作为视觉输入。
- 原有反应时间、MIX/HEAD/BODY 意图、精度、敌我强度和精英差异继续由现有模型控制。包括 Medium 普通敌人的 170 ms 基础 Reaction。
- BT 自身的反应等待设为零，避免与我们的反应过程叠加；原有模型负责首枪视角和开火许可。没有有效视觉计划时禁止原生攻击绕过模型。连续射击仍允许原生后坐力过程运行。
- 拆除、爆炸、回合结束、卸载时恢复先前入口。事件触发的销毁延迟到下一帧，避免在树自身执行栈中删除树。

行为树原生的移动/驻守逻辑、伤害转向与战斗走位仍然会带来不同体验；不能称为原系统所有行为完全不变。新桥接在烟雾/失去可见目标时优先阻止无视觉计划的原生射击，不保证沿用旧状态机的全部混烟行为。

## 实测与边界

本机独立回环服务器，竞技 Dust2，4 BOT，受控创建 C4 并发送下包事件：

- 4 个 BOT 的原生行为树指针均成功创建。
- 两名 CT 中同一时刻只有一名拆包；观测到真实开始拆包事件和一次成功拆除。
- T 守包场景中，两名 T 分别移动约 532 / 585 单位，进入炸弹周边的不同位置。
- HEAD 战斗场景观测到 128 次开火、72 次命中、15 次头部命中，原有模型恢复非零状态及反应/甩枪/跟枪阶段。高生命值、固定放置场景不能作为普通对局爆头率或强度评估。
- 拆除及回合结束后，树路径恢复为空，4 个 BOT 的树指针恢复为零。
- 271 项模型/阶段策略检查、12 项姿态检查、3 项 KV3 结构与模块依赖检查通过；两个插件 Release 构建成功。

测试不是完整自然 5v5 对局或十张图实战认证。临时探针已移走，测试挂载恢复；CS2 14197 底层兼容库不变。
