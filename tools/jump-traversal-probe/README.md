# 本地跳跃回归观察组件

仅在 Windows 独立回环专服使用。组件会改变该测试进程的队伍、回合、导航目标与机器人位置；不是正常对局插件，不放进日常运行目录长期保留。

固定输入为 `cases.json` 中九条导航连接：Dust2、Mirage、Inferno 各三处。先核对地图 VPK 哈希，再检查起点、落点地面和头顶空间。地图更新后应重新导出并审查坐标，不沿用失效连接。

每个点位从静止站姿分别以正对目标、偏转 60 度起步。等待实际冻结结束至少 4.25 秒，排除冻结和开局切刀窗口后才计时。只在每次开始时重置位置、视角和速度；观察组件在测试过程中不额外强制镜头、起跳按钮或位置。候选模块自身的辅助属于待测行为。将该 BOT 的原生移动目标请求限定在待测落点，保留原生路径、碰撞和动作执行。记录真实坐标、速度、离地、落地、卡住和路径状态。

8 秒内到达落点区域或其中心 32 单位以内、高度误差小于 16 单位，并稳定触地至少 0.12 秒算通过。结果中的 `jumps` 用于区分走上去、一次跳过或反复尝试；通过不等于毫无停顿。该测试不代表自然对局成功率。

## 使用条件

- 使用已验证的 CounterStrikeSharp 运行环境和 API 编译本项目。
- 备份待比较模块、设置和 gameinfo；用户游戏退出后启动独立测试进程。
- 测试组件只接受同时包含 `-jump-audit -dedicated -insecure -ip 127.0.0.1 -port 27025` 的启动方式，并需额外传入 `-jump-audit-root` 和 `-jump-audit-run`。
- `-jump-audit-root` 指定单独的证据目录，其中放置本目录的 `cases.json`。`-jump-audit-run` 是仅含英文字母、数字、下划线或连字符的全新记录名，拒绝覆盖旧记录。
- 启动地图为 `de_dust2`，后续自动切换 Mirage、Inferno。不要连接公开服务器或用户正在玩的服务器。
- 两个版本使用同一组坐标、角度、时限和目标限定方式。结束后退出自建进程，移出该观察组件，并恢复原模式文件。

构建：为 `JumpProbe.csproj` 设置 `CounterStrikeSharpApiPath` 到当前安装的 API 目录。临时安装文件名应与输出 `JumpProbe.dll` 一致。

比较完整的两份记录：

```powershell
python tools/audit_jump_trials.py --baseline <基线.jsonl> --candidate <候选.jsonl> --out <比较结果.json>
```

具体实施、结果和限制见 [Custom 8.60 跳跃审查](../../docs/JUMP-AUDIT-8.60-20261115.md)。
